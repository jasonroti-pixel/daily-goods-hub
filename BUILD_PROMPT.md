## WHAT TO BUILD — eight pages, tab navigation, one index.html
Tab order: Feeds, Newspaper, Builder, Interviews, Corkboard, The Keep, Archive, Tools & Resources. The Builder is the default landing tab: it is what the team opens every day.

### Page 1: Feeds (story-scout outputs, raw, read-only)
One unified feed. The reader NEVER sees which scout a story came from: no source panels, no source labels, no source badges anywhere on this page. Origin stays in the data model only (it feeds the duplicate filter).
- Fetch both JSONs in parallel on first visit and on Refresh (permissive CORS on raw.githubusercontent.com). Show a loading state ("Fetching scout feeds...") while the multi-MB files load; skeleton rows are fine. In-memory session cache so tab switches do not refetch.
- Normalize each record to {headline, url, source, category, bullets[], angle, date, slot, score}. Take the most recent `date` across BOTH sources. DEDUPE (not merge): same URL, or same normalized headline (lowercase, strip punctuation/whitespace), appears exactly once. No dual badges.
- 5-DAY ROLLING HISTORY: every successful fetch upserts the latest scout day's deduped stories under that scout date in the store; keep the 5 most recent scout dates, prune older. Render day groups newest-first with headers ("Friday, Oct 16 (47 stories)"). Same-day refreshes update in place, never duplicate. If one day exceeds ~300 stories, render the top 150 by score and note the cap.
- SUNDAY NOON REFRESH (America/Toronto): when the most recent Sunday 12:00 PM Toronto time is newer than the last wipe marker, clear the feed history AND the saved stories AND the tombstones, then set the marker. During the week the feed populates by day (5-day rolling history). After the Sunday wipe, a calm empty state ("Feed cleared Sunday afternoon. Fresh stories start Monday.") with no fetching until Monday. Monday starts a fresh 5-day accumulation. A missed Sunday wipe still runs on the next load.
- Each card expands (headline, bullets, URL, actions). THREE ACTIONS per card: (1) "Add to Today's Show": reveals a segment dropdown with the six segments and time slots; picking one creates the card in that builder lane immediately. (2) "Save for Tomorrow": pins the story into its own section at the bottom of the tab; saved stories survive every refresh. (3) "Delete": removes the story and tombstones it (by URL or normalized headline) so refreshes never resurrect it; a "Restore deleted" control lists tombstoned stories with restore buttons.
- Every card also has "Send to newspaper" (copies into the Newspaper as a scout item, deduped by URL).
- Failure: per-source inline error with a Retry button; the tab never renders empty without an explanation. The feeds never block the rest of the app.
- This page never edits story data. Raw means raw.
- Feed A: `https://raw.githubusercontent.com/jasonroti-pixel/story-scout-next/main/data/stories.json` (~6MB). Envelope: `generated_at, timezone, date, slot, pipeline_version, count, stories[]`. Story fields: `id, date, slot (am|pm), category, title, angle, bullets[], debate, source, source_type, url, score, is_backup, entities{people[], organizations[], locations[], is_canadian}, sentiment{compound,label}, summary, cluster_id, related_count, clips[{type,platform,url,thumbnail_url,duration_seconds,description}], meta{ingested_at, source_published_at, pipeline_version}`.
- Feed B: `https://raw.githubusercontent.com/jasonroti-pixel/daily-goods-rundowns/main/stories.json` (~3.75MB). Plain JSON array. Fields: `date, slot, category, title, angle, bullets[], debate, source, url, score, is_backup`.
- DECOUPLING CONTRACT: the hub depends only on the JSON shapes above. All parsing lives in one `feeds.js` adapter with the expected schema noted at the top. If a feed's shape changes, do not break: keep serving the last good cache and show a plain banner ("A story feed changed its format. Showing cached stories."). Nothing else in the app touches raw feed payloads.

## AUTOSAVE + CRASH RECOVERY (headline requirement, milestone 1)
Every state mutation writes synchronously to localStorage; there is no save button and no "unsaved changes" state. Rich-text content saves on text-change (debounced ~500ms). Keep the last 3 full snapshots under timestamped keys (`dg-hub-v1-backup-<ts>`); if the primary key fails to parse, fall back to the newest intact backup automatically. Nothing was lost.") with state already restored. Settings page keeps manual JSON export/import as the belt-and-suspenders backup. Verify the crash path yourself: simulate a crash by clearing the clean-exit flag and reloading mid-edit, and confirm every keystroke is restored.
